# Skill: reminder-config

用户用对话改提醒设置时，把原话交给确定性配置引擎处理。引擎已实现：`src/config_edit.py`，
入口脚本：`scripts/configure.py`。**智能体只负责转发原话、展示预览、等用户确认，绝不自己
算新值、绝不跳过预览直接写入**——字段、范围校验、旧值→新值全在引擎里，有单元测试覆盖。

## 用法
```bash
python3 scripts/configure.py "课前提前20分钟提醒"          # 预览变更计划（不写入）
python3 scripts/configure.py "课前提前20分钟提醒" --apply  # 用户确认后才加 --apply 写入
python3 scripts/configure.py "我现在的提醒设置是怎样的"      # 查看当前设置（只读，无需 --apply）
python3 scripts/configure.py "关掉高数的前晚提醒" --json   # 结构化计划，给智能体消费
```
- 改配置是**写操作**：流程固定为「转述原话 → 跑预览 → 把计划（改哪个文件、哪个字段、
  旧值 → 新值）原样给用户看 → 用户明确同意 → 才带 `--apply` 重跑」。用户没点头之前，
  任何情况下都不许加 `--apply`。
- `--apply` 写入前会自动给被改的文件生成时间戳备份，只改计划涉及的文件
  （全局偏好只动 user.json，单课覆盖只动 courses.json）。
- 查看设置是只读的，直接给 `configure.py` 那句问话即可，不需要确认环节。

## 支持的说法（引擎能锚定的就这些，之外会明确说没听懂）
- 全局数值/时间：前晚提醒时间（“前晚提醒改到20:30”）、课前提前量、默认路程、缓冲、
  雨天加量、恶劣天气加量、追问宽限、静默时段（“静默时间改成23:30到7:30”，要给起止两个时间）。
  分钟数范围 0–180，时间必须是合法 HH:MM；“多提前5分钟”这类说法按「现值 ± 5」算，
  预览里会注明并展示旧值 → 新值。
- 类型开关（四类：前晚 / 出门 / 课前 / 追问）：“关掉前晚提醒”“打开课前提醒”。
- 单课覆盖：点名课程（全名或简称：高数、大英、英语、程序设计，与 notice-parser 同口径）——
  “高数出门提前50分钟” 改该课的出门提前量；“关掉高数的前晚提醒” 只关该课这一类。
- 查看：“我现在的提醒设置是怎样的” → 列出全局偏好、各类型开关与所有单课覆盖。

## 待确认时如何追问（不可跳步、不可替用户定值）
引擎返回待确认（CLI 退出码 1）时，把原因原样转达并按缺口追问，不要换个说法重试写入：
- **没给具体数值**（“课前提前一点”）→ 请用户给一个 0–180 的分钟数；绝不替他猜一个数。
- **数值/时间不合法**（提前 1000 分钟、25:70）→ 告诉他允许的范围，请他重给。
- **课程多义**（简称同时匹配多门）→ 列出引擎给的候选全名，请用户指明哪一门。
- **点名课程但字段只有全局版**（如“高数课前提前20分钟”，课前提前量没有单课版）→
  把引擎的两个选项转达给用户：改全局，或改这门课的出门提前量；等他选，不许自作主张改全局。
- **没点名就说改出门时间** → 全局出门时间是路程+缓冲两项，请用户选改哪一项，
  或点名课程改单课出门提前量。
用户补全后，把补全后的完整说法重新交给 configure.py，走一遍新的预览 → 确认 → --apply。

## 硬规则
- 预览里的旧值 → 新值就是最终写入的值；用户对预览有异议就停，不要“帮他调整一下”直接写。
- 引擎标待确认 = 一律不写（CLI 即使带 --apply 也会拒绝，退出码 1），不要绕过引擎
  直接改 data/*.json。
- 改完后如实复述引擎结果（写了几处、备份文件名）；下一 tick 起新设置生效，
  已发送的提醒状态不会被改配置重置（scheduler 的合并逻辑保证），可以这样安抚用户，
  但不要承诺已发出的提醒会被撤回。
