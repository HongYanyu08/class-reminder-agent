# Skill: course-query

用户用对话问课表时，把原话交给确定性查询引擎回答。引擎已实现：`src/query.py`，
入口脚本：`scripts/ask.py`。**智能体只负责转发问题和复述答案，绝不自己算课、编课**——
周次、单双周、假期、调休、调课例外全在引擎里经 `expand()` 计算，有单元测试覆盖。

## 用法
```bash
python3 scripts/ask.py "明天有什么课"                          # 直接打印可读答案
python3 scripts/ask.py "下节课是什么" --date 2026-09-07T07:30:00   # 指定参照时刻（默认现在）
python3 scripts/ask.py "高等数学什么时候上" --json               # 结构化输出，给智能体消费
```
- 何时用 `--json`：需要把结果再加工（拼进提醒、做判断、取 occurrences 字段）时；
  只是回答用户时用默认文本输出，原样复述即可，不要改写其中的时间/教室/老师。
- `--date` 是参照日/时刻：用户在对话里提到“今天是几号”或做历史/未来复现时才传；
  平时不传，引擎按当前时刻算。相对日期（明天、本周三）都以它为锚。

## 支持的问法（引擎能锚定的就这些，之外会明确说没听懂）
- 按日期查：“今天/明天/后天有什么课”“本周三/下周一有什么课”“9月16日有什么课”“第3周周五有什么课”
- 按课程查：“高等数学什么时候上”“英语课在哪上”“程序设计要带什么”“数学老师是谁”
- 下节课：“下节课是什么”；本周概览：“这周还有什么课”
- 组合：“明天高等数学有课吗”（给日期 + 点名课程）

## 回答口径（引擎已保证，智能体不要破坏）
- 课程按全名或核心名匹配（大学英语→英语、高等数学→数学、程序设计基础→程序设计），
  与 notice-parser 同一口径。
- **例外如实说**：被停课的那次会在答案里以“已停课”出现，不会默默消失；
  调课的在新日期出现、原日期注明已调走；换教室/线上按新地点显示。
- 答案里没有的信息就是没有，不要替用户脑补（比如没登记携带物品就说没登记，
  不要建议“记得带课本”）。

## 澄清流程（不可跳步）
引擎返回 `kind=clarify` 时（文本输出同样是澄清话术），把问题原样抛回用户，不要替他选：
- **日期锚不准**：只说“周三”没说哪一周 → 请用户补“本周三 / 下周三 / 具体日期”；
- **课程多义**：简称同时匹配多门课 → 列出候选全名，请用户指明是哪一门；
- `kind=unknown`（没听懂）→ 把引擎给的支持问法示例发给用户，引导他换个问法。
用户补全后，把**补全后的完整问句**重新交给 ask.py，不要把上次的半成品结果拼着用。

## 硬规则
- 查询是只读的：ask.py 永远不写 data/，也不需要 `--apply` 之类的确认环节。
- 答案只许来自引擎输出：模型不许凭记忆/常识补充课程、时间、教室；
  引擎说没课就是没课，说待确认就走澄清流程。
