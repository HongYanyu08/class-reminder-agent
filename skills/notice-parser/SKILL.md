# Skill: notice-parser

把班群调课/停课通知变成 data/exceptions.json 里的一条 CourseException。解析器已实现：
`src/notice_parser.py`，入口脚本：`scripts/parse_notice.py`（默认预览，加 `--apply` 才写入，
写入前自动备份 exceptions.json）。确定性代码解析，不靠模型猜——DeepSeek/智能体只负责
把通知（或截图 OCR 结果）以原文送进解析器、把预览复述给用户确认。

## 支持的通知（一条通知 = 一条变更）
- **停课**：`高等数学 2026年9月21日停课一次` → cancel（只取消这一次）
- **调课**：`大学英语 2026年9月16日（周三）的课改到周五线上上课` → reschedule
  （新日期可写完整日期，也可写“周X”=原课所在周的周X、“下周X”=下一周的周X；带“线上”则带线上地点）
- **换教室**：`高等数学 2026年9月21日换教室到教三A301` → location_change
  （只给教室号如 `A301` 时 building 留空，绝不编造教学楼）
- **改线上**：`大学英语 2026年9月16日改为线上上课` → online（同日，只换上课方式）

## 锚定规则（硬规则，代码强制）
- 必须定位到 courseId + originalDate 两个锚点，缺一不可：
  - 课程按全名或核心名匹配（大学英语→英语、高等数学→数学、程序设计基础→程序设计）；
    匹配不到或同时匹配多门 → 标“课程待确认”
  - 日期优先认完整日期（2026年9月30日 / 2026-09-30 / 9月30日，年份缺失时按学期推断）；
    “第N周周X”按 term.json 锚定；“本周/下周/明天”只有在调用时给了通知日期
    （CLI `--date`）时才能锚定；裸“周三”、无参照的“下周三” → 标“原日期待确认”，绝不猜
  - 锚到的日期会校验：必须是这门课真实的上课日（星期 + 单双周 + 非假期），否则标待确认
- 只影响单次课，永不修改 courses.json 的周期模板
- 同一门课同一天已有另一类变更时视为冲突，拒绝自动写入，等人工裁决

## 流程（不可跳步）
`parse_notice.py "通知原文"` 预览 → 用户确认（重点核对 ⚠ 待确认，有待确认项时 `--apply` 会拒绝写入）
→ `--apply` 写入（去重：同课+同日+同类型视为重复；写入时 confirmed 置 true）
