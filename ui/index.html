发送渠道

提醒最终从哪个通道发出去，在这里配。保存后调度器（run_scheduler --tick --send）就按这里的设置发送；如果部署环境里设了 REMINDER_* 环境变量，环境变量优先生效，本页会标明来源。

先说清楚：个人微信没有官方机器人接口，本页不能、也不会假装直连个人微信。
能真正把提醒推到微信的现成路径是 webhook 中转：企业微信群机器人、Server酱、PushPlus、WxPusher 这类服务会给你一个 https 的 webhook 地址，填到下面即可；或者走你自己的 OpenClaw 网关（网关命令通道，由你的 OpenClaw 把消息发到它接好的渠道）。
webhook 地址等同于密码：只保存在本机 data/sender_settings.json（已 gitignore，不进仓库），页面上只显示打码版，不要外传、不要截图发群。

主会话投递不需要填任何东西：到期提醒先排进 data/session_outbox.jsonl（状态 queued），再由 OpenClaw 主会话里的 agent 在心跳时逐条原样说到当前会话，说完用 --confirm-sent 回写为 sent。微信 ClawBot 部署就用这一项——iLink 只接受带入站上下文令牌的出站消息，裸的发送命令会被拒绝（ret=-3），只有主会话里的 agent 亲口发才送得出去。

每条提醒追加一行 JSON 到该目录的 outbox.jsonl，适合本地验证或给 OpenClaw 侧消费。

备用通道（主会话兜底）

只对 session 主会话通道生效：微信的 context token 长时间没互动会失效（典型场景：过夜后早晨第一条出门提醒排着队却送不出去）。开启备用通道后，一条提醒排队（queued）超过下面设定的分钟数还没被确认送达，调度器会在 tick 内部自动改走 Server酱 / PushPlus 补发——不依赖 token，补发成功即记为已送达。session 之外的通道不使用这里的设置。

需要先在对应服务注册并拿到 key（见 DEPLOY.md 故障排查）。
从第一次排队算起；留空 = 默认 15；范围 5–120。
等同密码：只保存在本机 data/sender_settings.json，页面只显示打码版。保持打码版原样保存不会把真 key 冲掉；想换就清空后粘贴新的。

两个测试按钮都用当前页面上填的设置（草稿，不先保存）发一条固定测试文案，通不通当场见分晓；失败会显示具体原因。测试不会改动已保存的设置。

导入课表

两种方式任选：上传课表文件（.txt / .csv / .xlsx / .json，最大 2 MB），或者把课表截图转成的文字直接粘贴进来。先点「预览解析」核对，确认无误再点「确认导入」——和命令行导入一样，没点确认之前不会写入任何文件，写入前会自动备份。

关于「待确认」：识别不准的字段（教室、教师、周次等）会被标成待确认，系统绝不猜。和命令行导入的行为一致：带待确认的课程会照常导入，待确认字段留空、不会被编造填充，预览里会逐条高亮列出，导入后请核对修正。
支持 .txt / .csv / .xlsx / .json，最大 2 MB。选了文件就以文件为准（与粘贴文字二选一）。
课表截图先让智能体转成文字，再把文字粘到这里。

本地工具仅监听 127.0.0.1、无鉴权。不要把端口暴露到局域网或公网。
